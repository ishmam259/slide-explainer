# Slide Explainer

**An AI agent that turns confusing lecture slides into a detailed, cited study document.**

| | |
|---|---|
| **Team** | A K M Ishmam Tahmid — ID 220041259 (solo project) |
| **Course** | AI Workshop — Final Project Showcase |

## Description

Lecture slides are often just keywords, unlabelled diagrams, or "see lecture" — useless when you
study alone later. Slide Explainer is an agentic AI tool that reads a whole deck (PowerPoint, PDF,
or phone photos of a projector), works out what each slide is trying to teach (even the vague
ones, with a stated confidence), researches **lawful, freely available** books and web pages for
the topics, filters out spam, paywalls and prompt-injection attempts, and writes a detailed
explanation of every slide in which **every paragraph cites its evidence** (slide number, book
page, or web section) — exported as PDF, Word, Markdown, or HTML. It then answers questions and
quizzes you using only those sources, and declines when the sources don't cover a question
instead of making something up. The learner stays in control: nothing that costs money runs
without a cost estimate and a click, and only sources the learner approves are used.

## Quick start (judges)

You need **Windows 10/11** (or macOS/Linux), **[Node.js LTS](https://nodejs.org)**, and
**[uv](https://docs.astral.sh/uv/)** — uv downloads the right Python by itself.

```powershell
# install uv once (Windows PowerShell), then open a new terminal
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

git clone https://github.com/ishmam259/slide-explainer.git
cd slide-explainer
.\start.ps1            # macOS/Linux: ./start.sh
```

The first run installs everything (~3–5 minutes), then opens <http://localhost:3000>.

**Demo mode (default) needs no API key and costs nothing.** It uses a built-in offline model and
a bundled offline "web", so the whole workflow can be tested. Its explanation text is placeholder
wording, and the costs it displays are simulated — the header says *demo mode*. To see real
output without running anything, open
[`samples/output/`](samples/output/) (documents generated by the live agent).

**Try it:**
1. Upload `samples/vague-lecture.pdf` (a deliberately bad 25-slide deck: keyword-only slides, an
   unlabelled diagram, "See lecture", and one factually wrong claim).
2. **Slides** tab — see each slide's clarity rating; vague slides can take a hint from you.
3. **Sources** tab — review the estimate, *Confirm and research*, then approve sources. The spam,
   prompt-injection and paywalled pages are filtered out automatically.
4. **Document** tab — choose PDF and/or Word, *Write the document*, download.
5. **Ask & quiz** tab — ask a question; take a quiz with a hint ladder.

**Live mode (real AI, about $0.40 for a 25-slide deck with a 6-topic research budget (`SLIDEX_MAX_TOPICS=6`, `SLIDEX_SEARCHES_PER_TOPIC=1`, `SLIDEX_PAGES_PER_TOPIC=3`); almost all of it is web-search fees):** copy `backend/.env.example` to
`backend/.env`, set `OPENAI_API_KEY=sk-…`, then run `.\start.ps1 -Live` (`./start.sh --live`).

Optional: [LibreOffice](https://www.libreoffice.org/) is needed only for `.pptx` uploads (PDFs and
images work without it). `GET http://127.0.0.1:8000/health` shows what's available.

## How it works

```
 upload ─► extract ─► interpret ─► topics ─► ⏸ confirm cost ─► research ─► safety filter
 (PPTX/PDF/   (text, OCR/   (vague slides     (estimate,      (search, fetch,  (spam, paywall,
  images)      vision)       reconstructed)     you approve)    robots.txt)      injection)
                                                                    │
     Q&A + quiz ◄── render PDF/Word/MD/HTML ◄── explain + cite ◄── ⏸ approve sources ◄─┘
   (grounded,          (Chromium, KaTeX,        (every block must     (books → RAPTOR tree,
    declines)           python-docx)             cite evidence)        web → sections)
```

- **Agent orchestration:** a LangGraph state machine with two human-in-the-loop pauses (cost
  confirmation, source approval) and a SQLite checkpointer, so a crashed or cancelled run resumes
  without paying twice (model calls are cached).
- **Understanding bad slides:** native text + OCR/vision extraction, then a reasoning model
  reconstructs vague slides using neighbouring slides and course context, with a confidence score
  and a "needs your input" flag.
- **Research you can trust:** only open sources (OpenStax, LibreTexts, MIT OCW, arXiv, Wikipedia,
  university notes…); `robots.txt`, rate limits and an SSRF guard are enforced; fetched text is
  wrapped as untrusted data and checked for prompt injection before any model sees it.
- **Books:** long PDFs are indexed as a RAPTOR tree (embeddings → PCA → Gaussian-mixture clusters
  chosen by BIC → recursive summaries) so retrieval works at passage, chapter and theme level, and
  book diagrams are captured and explained.
- **Grounding:** every generated block must cite known evidence IDs; uncited blocks and filler
  phrases are rejected and regenerated.
- **Cost control:** every expensive step shows a per-stage estimate first; estimates calibrate
  themselves from actual spend.

## Tools and technologies

| Area | Used |
|---|---|
| AI | OpenAI Responses API — `gpt-5.4-nano` (reasoning, vision, web search), `text-embedding-3-small`; structured outputs (Pydantic) |
| Agent | LangGraph 1.x with SQLite checkpoints and interrupts |
| Backend | Python 3.14, FastAPI, Pydantic 2, SQLAlchemy 2 + SQLite, uv |
| Documents | PyMuPDF, python-pptx, LibreOffice (headless), Pillow, RapidOCR (optional GPU) |
| Retrieval | NumPy cosine search, scikit-learn (PCA, Gaussian mixtures) for RAPTOR, tiktoken |
| Web research | httpx, trafilatura, robots.txt parser |
| Output | Playwright Chromium (PDF), KaTeX (formulas), python-docx, Jinja2 |
| Frontend | Next.js 16 (App Router), React 19, TypeScript, Tailwind CSS 4, shadcn/ui, Zod, Server-Sent Events |
| Quality | pytest (213 offline tests, fake model + mocked web), Ruff, mypy strict, ESLint, Vitest, Playwright |
| Process | Spec Kit spec-driven development (`specs/001-slide-explainer/`) |

## Privacy and safety

Everything runs locally; slides and documents never leave your machine except as model requests
to OpenAI in live mode. The API key stays in `backend/.env` on the server side and is never sent
to the browser. Only legally free sources are used; paywalled books are listed as further reading.
